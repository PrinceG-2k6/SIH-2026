0. ONE-SENTENCE PITCH
---------------------
ORIGIN is a hackathon prototype that predicts oil production and equipment failure risk for Baghewala cyclic-steam wells, then recommends feasible CSS (steam) + SRP (pumpjack) setpoints, and shows them on a dashboard plus a 3D/2D digital twin.

It is a DECISION-SUPPORT DEMO, not a calibrated field control system.


1. HARD DISCLAIMERS (ALWAYS SAY THESE)
--------------------------------------
- Data is SYNTHETIC (generated in code to look physically sensible).
- Models are trained ONLY on that synthetic data.
- Constraint limits in config.py are DEMO ASSUMPTIONS, not official OIL operating limits.
- Predictions / recommendations must NOT be presented as guaranteed field outcomes.
- The 3D twin is a schematic replica driven by model outputs, not a photogrammetry scan of a real well.


2. DOMAIN (WHAT THE PROBLEM IS ABOUT)
-------------------------------------
Baghewala Field (Rajasthan) produces heavy oil. Operators use:

CSS — Cyclic Steam Stimulation
  Inject steam → soak → produce. Heat lowers oil viscosity so oil can flow.

SRP — Sucker Rod Pump (pumpjack / nodding donkey)
  Surface beam pump lifts oil through rods and tubing.

The engineering trade-off:
  More steam / faster pumping can raise offtake, but can worsen Steam-Oil Ratio (SOR), energy per barrel, rod load, rod floating, and failure risk.

ORIGIN’s job:
  1. Predict what happens if we use these CSS+SRP parameters.
  2. Search feasible parameters and recommend a balanced (and Pareto) set.
  3. Compare current vs recommended.
  4. Let operators what-if simulate and watch a live twin.

----------------------------
Demo CSV  →  SQLite (well_records)
          →  preprocess + features

          →  Constrained grid optimizer + Pareto selection

10. ML MODELS (PYTHON — NOT THE 3D SCENE)
-----------------------------------------
This is classical supervised ML. Not deep learning. Not an LLM.

A) Production forecast — REGRESSION
   Target: oil_rate_bopd
   Candidates: LinearRegression, RandomForestRegressor, XGBRegressor
   Selected typically: RandomForest (highest R²)
   RF params: n_estimators=100, max_depth=8, random_state=42
   XGB params: n_estimators=120, max_depth=6, learning_rate=0.08, objective=reg:squarederror
   Metrics (see models/metrics.json; can change after retrain):
     MAE ~ 0.84, RMSE ~ 1.08, R² ~ 0.93, holdout n=108

B) Failure risk — CLASSIFICATION
   Label = 1 if failure_probability > 0.45 OR rod_failure_event==1 OR pump_unsetting_event==1
   Candidates: LogisticRegression, RandomForestClassifier, XGBClassifier
   Selected typically: LogisticRegression (highest F1)
   LR params: max_iter=500, random_state=42
   Metrics typically: F1 ~ 0.97, ROC-AUC ~ 0.99
   (High scores because labels are generated from the same synthetic physics — expected for a demo.)

Validation: chronological 80/20 split (time-ordered, not shuffled).

Feature columns (FEATURE_COLUMNS + engineered):
  reservoir_temperature, reservoir_pressure, oil_viscosity, oil_api, water_cut
  steam_volume, injection_pressure, injection_duration, soak_time
  stroke_length, spm, vfd_setting
  pump_efficiency, rod_load, sor, energy_per_barrel
  production_change, temperature_change, viscosity_change
  rolling_production (7-day), rolling_sor (7-day)

Inference path (predictor.py):
  latest SQLite state → overlay proposed parameters → preprocess → feature matrix
  → production.predict → oil rate
  → failure.predict_proba[:,1] → failure probability
  → derive temp/viscosity/SOR/energy/pump/rod/floating with formulas

Saved artifacts (binary dumps, not editable source):
  models/production_model.joblib
  models/failure_model.joblib
  models/metrics.json

Retrain:
  Automatic if files missing.
  Force: train_models(force=True) or POST /api/data/import (CSV upload retrains + invalidates optimizer cache).


11. OPTIMIZER
-------------
Not an ML model. It CALLS the prediction models.

Steps:
  1. Build compact grid of CSS+SRP combinations (~72 after cap).
     steam: 400,500,580,650
     pressure: 7.5, 8.5
     duration: 72
     soak: 48, 60
     stroke: 2.2, 2.5, 2.8
     spm: 5, 6, 7
     vfd: 65, 80
  2. Drop anything outside config bounds.
  3. predict() each candidate.
  4. Score = wp*oil − ws*SOR*10 − we*energy_per_bbl − wf*fail*100 − rod over-limit penalty − fail over-cap penalty.
  5. Best score → recommended (label "balanced").
  6. Pareto front on (max oil, min SOR, min failure) → up to 3 labeled options:
     option_a_production / option_b_efficiency / option_c_reliability
     (or production_focus / efficiency_focus / reliability_focus as fallback)

Cached per well/weights so dashboard reloads are faster.

17. SYNTHETIC PHYSICS (GENERATOR)
---------------------------------
backend/app/data/generator.py

Intuition baked into demo data:
  Higher temperature → lower viscosity (exponential-ish)
  Production rises with mobility (temp/viscosity), steam factor, SRP factor (spm*stroke*η)
  SOR ≈ steam / oil * 0.08
  Pump efficiency falls with high viscosity, high SPM, long stroke
  Rod load rises with viscosity, SPM, stroke
  Failure rises with floating, high rod load, low pump η

This is WHY ML can fit well: labels and features come from the same generator.

20. WHAT TO SAY IF ASKED “WHAT MODEL?”
--------------------------------------
Two models:
  RandomForest (typically) predicts oil rate.
  LogisticRegression (typically) predicts failure probability.
Both trained with scikit-learn/XGBoost comparison on synthetic Baghewala CSV.
Optimizer is a constrained search over those predictions, not a third trained model.
3D “model” is Three.js geometry in DigitalTwinScene.tsx.


21. COMMON FAILURES
-------------------
WinError 10013 on bind: port occupied. Use 8088; kill leftover uvicorn.
Blank Overview / Analyzing forever: backend down, wrong Vite proxy port, or optimizer still running (~seconds).
ECONNREFUSED on /api: backend not started.
Models “too good”: synthetic labels — expected; do not claim field accuracy.
Do not open .joblib as source code — they are serialized sklearn objects.
